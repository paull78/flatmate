## Decisions

| Decision | Why | Spec |
|----------|-----|------|
| Pointer events carry **screen coordinates only**; editor owns the camera | One camera authority (critique 1) | §5.2 |
| Wall tool has an **exact transition table**; typed length goes along the current (snapped, Shift-constrained) cursor direction | Lengths alone don't define directions (critique 1) | §5.5 |
| `Enter`/`Space` + value → place point; empty → finish; clicking `chainStart` closes (2026-09-27) | One closure method is enough for the demo | §5.5 |
| `Space` never pans; pan = middle-drag / trackpad; zoom = Ctrl/pinch + wheel | Space confirms, like Enter | §5.4 |
| `Cmd+S` saves a local file now; no-op for in-memory and shared documents (2026-09-26) | Autosave covers the rest | §5.4, §7.0 |
| Key precedence: value field → command codes → global (2026-09-27) | No initial tool mode key or `DI` chord | §5.4 |
| Gestures: preview on `baseDoc`, **one changeset on release**; invalid preview drawn red and reverted; 4 px drag threshold | Live feedback, one undo step per gesture | §5.7 |
| Remote change during gesture: remote topology change or overlap with the gesture's semantic dependencies → **cancel** ("Drawing changed remotely"); otherwise rerun on the new visible doc; snapshots cancel all | Simplest safe policy (critique 2) | §5.7 |
| Selection: one entity; pressing an unselected entity selects it at once so one press can select and drag (2026-09-27); handles beat bodies; pressing a handle of the selected wall drags that joint (selection stays on the wall); moving a wall moves its two endpoints; deleting a joint deletes incident walls (2026-09-27) | No multi-selection or box logic for the demo | §5.6 |
| Helper dimension keeps endpoint `a` fixed and marks it; endpoint switching deferred | Simplest | §5.6 |
| While editing, the helper plate looks like a text field: blue outline; light blue fill with the current length until the first key, then white with the typed value (2026-09-30, U2) | Clicking the length gave no visible change on the canvas; only the command bar said "Wall length" (user report) | §5.6 |
| Snapping: endpoint, midpoint, on-wall, grid policies (priorities 1–4) → candidates → pure chooser (priority, then distance), 10 px tolerance; Shift before chooser, Ctrl bypass (2026-09-27; midpoint restored the same day) | On-wall outranks grid, so exact points on a wall come from endpoints or midpoints; the demo divider joins two wall midpoints | §5.8 |
| Snapping details (plan Task 3.4, 2026-09-28): grid step = smallest of 0.01…10 m that is ≥ 16 px wide; with Shift the axis is the dominant orthogonal direction from the origin, grid steps are counted from the origin, and on-wall is where the axis crosses a wall centreline within the segment; Ctrl skips the policies but keeps the Shift projection; exact ties break by x, then y | Deterministic, and typed or Shift-constrained points stay on the axis; the spec names only kinds, priorities, tolerance, Shift and Ctrl | §5.8 |
| Edits require `canCommit`; wall chains pause after each commit, resume on the `accepted` notice, end on `rejected` — a local document accepts at once, so no visible pause (2026-09-26). Explicit `paused` state in the wall table; resume checks the anchor joint, then recomputes the preview from the visible document; an invalid preview is shown red, not a reason to end the chain; a paused chain counts as an active gesture for §5.7 cancellation (2026-09-26). `chainStart` carries through `paused` so a resumed chain can still close (2026-09-27) | No buffered edits or dependent operations; camera/selection/presence remain available | §7.4 |
| Digits and `.` are read from the physical key (`code`) in the web input adapter, so typed lengths work while `Shift` is held; the typed direction uses the last pointer event's modifiers; modifier-only key events are ignored (2026-09-27) | On a US keyboard `Shift`+`6` is `^`, which broke demo step 2 (found while planning phase 8) | §5.4 |
| `EditorState` also holds `mode` (local or server start), `panDrag` (last screen point of a middle-button pan) and `snap` (current snap result for the glyph and ViewModel); switching to any tool, the active one included, resets its gesture (a `W` press mid-chain restarts the chain); `me.color` is `DEFAULT_ME_COLOR` until the server's `welcome` (2026-09-29, Task 3.7 review) | The plan added these fields; the spec lists the rest (§5.3) | §5.3, §5.5 |
| Blocked edits toast "Waiting for server", or "Offline: editing resumes when the connection returns" while offline (`blockedMessage`); rejections toast a fixed text per reason (`rejectMessage`) (2026-09-29, Task 3.8) | §7.4 says only "show reason" | §7.4 |
| `EditorState.pointer` keeps the last pointer position (world and mods) for typed-length directions and presence (2026-09-27) | The typed direction needs the cursor between events | §5.3, §5.5 |
| The cursor follows the camera: after a wheel, a viewport resize or the end of a middle-drag pan, `update` replays the last pointer move so `pointer.world`, the tool's preview/snap and presence match what is under the cursor. During a middle-drag pan the tool is not told (its preview may lag until the pan ends) and pan moves send no presence (a grab pan keeps the same world point under the cursor); right-button moves reach no tool but send presence (2026-09-29, wave 6 reviews) | A two-finger scroll mid-chain left the typed direction and preview 2 m off the cursor | §5.4, §5.5 |
| An undo or redo that applies (keys or toolbar) drops the gesture in progress (`switchTool` to the same tool) and replays the pointer so hover, snap and preview are rebuilt on the new document; a refused one ("Nothing to undo", "Waiting for server") only shows its toast (2026-09-29, wave 6 reviews) | A chain or drag preview built on the pre-undo document kept showing undone walls, and a chain could continue from an undone joint; dropping it on a refused undo lost the chain for nothing | §5.4 |
| The select tool's drag threshold is measured in world units at the current zoom (`distance(world, pressWorld) · zoom > 4 px`), so a scroll mid-press starts the drag and a zoom at the cursor does not (2026-09-29, wave 6 code review; landed with Task 3.12, spec §5.7 reworded) | With screen points, a scroll mid-press left the press "still" and the next small move jumped the entity back under the cursor | §5.4, §5.7 |
| Gesture dependencies for remote changes (`gestures.ts`): drag = moved joints + their incident walls; helper resize = wall, both endpoints, walls at the moving end; paused chain = its pending segment's history dependencies; drawing chain = its origin joint, checked by position (once a wall is placed, a joint must still be at the origin). Snapshots and disconnects cancel every active gesture. Toasts: "Drawing changed remotely — wall chain ended", "Drawing changed remotely", "Connection lost: editing resumes when it returns"; `rerunMove` rebuilds from `attempt.cursor` with `attempt.doc` reset to the new base, so an invalid rerun shows the current drawing (2026-09-29) | §5.7 names the rule but not each tool's set; the drawing state stores points, not joint IDs, so position is the simplest check | §5.5, §5.7 |
| A same-step rejection (the local `tooLarge` guard) leaves the wall tool unchanged, like an `execute` refusal (2026-09-29) | The chain must not advance past a wall that was never submitted | §5.5, §7.4 |
| Zone clicks select and highlight the floor; create a label first only for an unlabelled room. Selection references the label ID; properties rename, Delete removes only the label (2026-09-26) | Gives selection a visible shape and useful actions without stored room geometry | §3.6, §5.6 |

Planning-time readings for phase 3 (2026-09-27; confirm at gate 3): wall points are placed on `pointerDown`; only a click on `chainStart` closes a chain (a typed length that lands there does not); while paused, digits/`Enter`/`Space`/`Backspace` are swallowed; a wall drag moves by a grid-rounded delta and a joint drag snaps the joint itself, excluding its own walls (spec §5.6); a server `invalid` rejection names the broken invariant through the domain's shared table ("Walls can't cross" for I5–I7, "Wall too short" for I2, "Joints can't overlap" for I4; revised 2026-09-29, wave 5 code review) and falls back to "Rejected: the drawing would become invalid". The properties panel shows committed values (the visible document) while handles follow a drag preview (2026-09-29). Select and wall tools (Tasks 3.11–3.12, 2026-09-29): a click in `drawing` places at the click and clears any typed value (spec §5.5 row revised); clicking a handle of the selected wall without dragging keeps the wall selected (to select an endpoint joint, click it while the wall is not selected); a drag's release commits the last previewed moves, not a recomputation at the pointer-up (spec §5.7). Wave 7 code review: the nearest handle within 8 px wins (joint `a` on exact ties); a press whose target vanished before the drag starts ends the press; a typed length needs the same cursor-off-origin test as the preview (`< EPS`); a click on the chain's origin is ignored without a toast (spec §5.5 row); accepted: a document holding IDs that start with `preview/` turns every wall preview red (committed IDs come from `host.newId()`, so only a crafted file can). Key and pointer routing (Task 3.10, 2026-09-29): `Esc` in the idle Select tool clears the selection and in the Zone tool goes straight to Select; `Delete`/`Backspace` act only in the idle Select tool (or on a zone label in the Zone tool) and never with `Cmd`/`Ctrl`; `Ctrl+Z` also undoes and `Meta`+wheel also zooms; the right button reaches no tool (no context menu); value fields get the key without its modifiers (so `Cmd+Backspace` edits a typed value); any `pointerUp` ends a middle-drag pan; `Ctrl`+wheel zooms by `exp(-0.01·deltaY)`, fine for a trackpad pinch but 2.7× per 100 px mouse-wheel notch (check with a mouse in phase 4 or 8).

Planning-time readings for phase 5 (2026-09-27; confirm at gate 5): the helper sits on the left of a→b, 18 px beyond the wall face (`helperLabelAt` is the one placement function), and its text is hit-tested before everything else; a bad typed number keeps helper editing with a toast, a domain refusal ends it but keeps the selection; tags show the short "Area unavailable", properties the domain's reason; new labels go at the raw click point, named "Room N" (N = label count + 1, so names can repeat); a `Z` click outside a room keeps the selection, a Select click on an unlabelled floor clears it; the helper colour differs from the selection blue. **Confirmed at gate 5 (2026-09-29):** all kept for the demo. Helper editing: `V`/`W`/`Z` switch tools and drop the edit, `Esc` cancels and keeps the wall selected, a refused `Cmd+Z` keeps editing, and a wall that vanished ends the edit silently on the next key (phase 7 may end it when the remote change arrives). Below about 48 px/m the right wall's helper overlaps the neighbouring room's tag; the demo runs at 80 px/m.
| Wall tool drag: press on the first point, drag past 4 px, release → one wall to the snapped release point, chain ends (`idle`); a short release, or one that snaps back onto the first point (trackpad jitter; U1 review), is a click and the chain goes on; only the first point starts a drag (`dragFrom` set from `idle`, cleared on the first release) (2026-09-30, user report: the wall stayed "suspended" after a drag; user chose "one drag = one wall") | Click-click chaining stays; later presses already commit (and pause on shared documents), so a mid-chain drag would need a second commit path | §5.5 |
| Angle (15° rays from the origin, priority 5) and perpendicular (foot from the origin on a wall, priority 3) snaps, wall tool only, off with Shift/Ctrl; aligned moves to 6 and grid to 7; tie rule: an aligned line crossing the ray within the tolerance gives the crossing point (2026-09-30, §11 item 3; user chose 15° and wall tool only) | Exact directions without holding Shift, and the §11 "tie rules"; joint drags keep today's snaps because several walls meet at a joint | §5.8 |
| The grid snap is the fallback and ignores the 10 px tolerance; other snaps still need it (2026-09-29, user bug report: walls landed off-grid) | Grid cells are at least 16 px wide, so a tolerance-bound grid snap missed every cell centre and used the raw cursor | §5.8 |
| Aligned snap (priority 4, grid now 5): the point takes another joint's x and/or y when the cursor is within 10 px of it on that axis; the other coordinate stays on the grid; guide lines from the joints (`SnapResult.guides`, x first). With Shift only the axis's coordinate lines up. `SnapContext` now carries `tolerance` (the policy checks each axis; its candidate's `distance` is the offset to the line, so the chooser's check still holds) (2026-09-29, user bug report) | The grid step changes with zoom and the 1-2-5 grids don't nest (3.4 is not on the 0.5 m grid, 3.5 not on the 0.2 m one), so a joint placed at one zoom could never be lined up again at another: a divider could not be made vertical | §5.8 |
| Tag layouts cached per Host → document → zoom and shared by drawing and hit-testing, so panning lays out no tags (2026-09-30, P2) | Tag layout was 66% of a pan step at 50×50, computed twice per event | §5.9 |

## Don't

- Don't implement loop mode, `DI`, box/multi selection or coalesced arrow nudge in the initial editor (2026-09-27, §11).
- Don't cut the midpoint snap while the demo divider depends on it: without it the on-wall snap wins and the divider lands at the raw cursor (2026-09-27, §5.8).
- Don't define a paused state that drops `chainStart`: the closing click of a shared-document chain stops working (2026-09-27, §5.5).

- Don't create duplicate labels on repeated room clicks or rename directly on tag click; select the zone and edit through properties (2026-09-26).

- Don't write scenario tests with typed lengths but no pointer moves.
- Don't keep a gesture's preview across an applied undo or redo: it was built on the pre-undo document; but don't drop it on a refused one (2026-09-29, §5.4).
- Don't measure a drag threshold between screen points once the cursor follows the camera (2026-09-29, §5.7).
- Don't cache `pointer.world` across camera changes; derive it from `pointer.screen` with the current camera (2026-09-29, §5.4).
- Don't recompute a gesture against a remotely changed dependency — cancel it.
- Don't end a resumed wall chain just because the preview at the current cursor is invalid: preview validity depends on the cursor; show it red and let the next click's `execute` decide (2026-09-26, §5.5).
